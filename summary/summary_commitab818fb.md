## การปรับจากแผน (และเหตุผล)

1. **spiral อยู่ที่มุม cp3 ไม่ใช่กลางกระดาน**: ไม่มี checkpoint กลางกระดาน (จุด (18,18) เป็นแค่จุดที่ทางสองช่วงตัดกัน) ถ้าทำก้นหอยรอบจุดนั้น ครีปจะเดินอ้อมรอบนอกไป ก้นหอยจะบังคับครีปได้ก็ต่อเมื่อล้อม checkpoint ที่ครีปต้องเดินไปถึง ที่ cp3 (32,4) ขอบบนและขอบขวาทำหน้าที่เป็นกำแพงให้ฟรี กำแพงแต่ละวงจึงเป็นแค่รูปตัว L
2. **ไฟล์อยู่ที่ `src/data/blueprints/` และลงทะเบียนใน `index.ts`**: เพื่อให้ CLI, worker และเบราว์เซอร์ (รวมเว็บที่ deploy แล้ว) โหลดชุดเดียวกัน เพิ่มแปลนใหม่ = เพิ่มไฟล์ + เพิ่ม 1 บรรทัดใน index ห้ามเขียนทับไฟล์เดิม
3. **`validate` ข้อ c ยังตรวจทุก prefix ตามที่ขอ** แต่ในทางทฤษฎี ถ้าแปลนเต็มไม่ปิดทาง ทุก prefix ก็ไม่ปิดทาง (เอากำแพงออกไม่มีทางทำให้ทางตัน) ความเสี่ยงจริงคือหินหรือเจมนอกแปลนของบอทไปรวมกับแปลนแล้วปิดทาง บอทจึงข้ามช่องแปลนที่วางไม่ได้ในตอนนั้น
4. **สเกลของ `blueprintWeight`**: วัดจาก `w73` ช่องที่ดีที่สุดได้ 40–50 คะแนน อันดับ 1 ถึง 20 ต่างกันแค่ 5–10 คะแนน จึงกำหนดให้ช่องแรกของ window ได้ **10 × blueprintWeight** ค่า 5 ที่ใช้เทียบจึงเท่ากับ +50
5. **`slotKeepBonus` เป็นตัวคูณ** power × (1 + ค่านี้) ให้เข้ากับวิธีคิดคะแนนตอนเลือก keep ที่มีอยู่
6. **slot ทุกจุดยิงถึงทางบิน (100%)** เกินแนวทาง 20–30% เพราะเส้นทางบิน x=32 และ y=4 พาดผ่านก้นหอยนี้พอดี ถือเป็นข้อดีของแปลนนี้

## เครื่องมือ: `npm run blueprint -- <คำสั่ง>`

| คำสั่ง | ทำอะไร |
|---|---|
| `board` | กระดานเปล่า + ทางพื้น + ทางบิน |
| `render <id> [--level=N \| --pct=P]` | กระดานหลังสร้างตามลำดับถึงจุดที่ระบุ |
| `validate <id>` | อยู่ในกระดาน, วางได้, ไม่ซ้ำ, order ไม่ซ้ำ, ทุก prefix ไม่ปิดทาง, จำนวนช่องเทียบงบ |
| `stats <id>` | ความยาวทางตามด่าน 2/5/10/…/30 และ 25/50/75/100%, จำนวนช่องที่แต่ละ slot ยิงถึง, slot ที่ยิงถึงทางบิน |
| `reorder <id>` | จัดลำดับใหม่แบบ greedy (ช่องที่ทำให้ทางยาวขึ้นมากที่สุดก่อน) บันทึกเป็น id ใหม่ ไม่ทับของเดิม |

## บอทและ tuner

- **ค่าน้ำหนักใหม่**: `blueprintId` (ค่าแบบเลือก ค่าเริ่มต้น `none`), `blueprintWeight` (0–20), `blueprintWindow` (1–40), `slotKeepBonus` (0–3)
- **ตอนวาง**: ช่องแปลนที่ยังว่างและวางได้ตอนนี้ `blueprintWindow` ช่องแรก ได้โบนัส 10 × weight แล้วลดลงตามลำดับ บวกเข้ากับคะแนนเดิม (exposure ฯลฯ) ช่องนอกแปลนยังชนะได้ถ้าคะแนนสูงกว่า
- **ตอน keep**: เจมบน slot ได้ power × (1 + `slotKeepBonus`)
- **tuner**: ทุก candidate มีโอกาส 15% เปลี่ยน `blueprintId` เป็นแปลนอื่น (`--blueprints=` จำกัดตัวเลือกได้) ถ้าเปลี่ยนไปแปลนที่ weight เป็น 0 จะตั้ง weight เป็น 5 ให้
- **LLM**: คำขอมีรายการแปลนที่เลือกได้และสถิติของแปลน ข้อเสนอที่อ้าง id ที่ไม่มีจริงจะถูกตัดทิ้ง
- **`GameRecord`**: `blueprintAdherence` (สัดส่วนเจมที่ลงตามแปลนรายด่าน), `blueprintProgress` (order สูงสุดที่สร้างแล้ว), `blueprintBuilt` (จำนวนช่องแปลนที่สร้างแล้ว), `blueprintSlotsKept` (slot ที่ได้ tower ที่ keep)
- **รายงาน**: ส่วน "แปลน" บอกสัดส่วนที่ทำตามแปลน, แปลนสร้างไปถึงไหนตอนตาย, slot แต่ละจุดได้ tower บ่อยแค่ไหน และ slot ที่ไม่เคยได้เลย
- **Watch**: เงาแปลน (กรอบจาง = กำแพง, วงกลมทอง = slot, เลข order เมื่อซูมใกล้) คีย์ `B` หรือปุ่มในส่วน AI

**แก้ bug ของ rules hash** ด้วย: เดิม `src/ai/exposure.ts` ไม่ได้อยู่ใน hash ทั้งที่มีผลต่อการตัดสินใจของบอท ตอนนี้ hash ไล่ทุกไฟล์ใน `src/game`, `src/data` (รวมแปลน) และ `src/ai` ยกเว้นไฟล์ที่ใช้แค่วิเคราะห์ผล
