# สรุป commit `c7ffa6d` — Keep tuning runs apart and stop leaking LLM proposals

- **Branch:** `ai-sim` (ต่อจาก `ab818fb`)
- **ประเภท:** แก้ bug 3 ตัวที่เจอตอนเริ่มจูน spiral

## 1. id ของค่าน้ำหนักชนกันระหว่างการจูนคนละชุด

**อาการ:** การจูนใหม่เริ่มนับ id ที่ `w1` เสมอ แต่ทุกการจูนบันทึกค่าน้ำหนักลงโฟลเดอร์เดียวกัน (`sim-runs/weights/`) การจูน spiral จึงเขียนทับ `w1`–`w4` ของการจูนแรก รวมถึง `w3` ที่ผมเคยให้ลิงก์ replay ไว้ (`?ai=w3&seed=75`) ทำให้ลิงก์นั้นเปิดค่าน้ำหนักคนละชุด

**แก้:**
- `npm run tune -- --run=<ชื่อ>` แยกการจูนไปไว้ที่ `sim-runs/tune-<ชื่อ>/`
- id ใหม่มีชื่อ run นำหน้า เช่น `spiral-w1`
- ไม่ใส่ `--run` จะทำงานแบบเดิม (`sim-runs/tune/`, id `wN`)

**กู้ข้อมูล:** สร้าง `w1`–`w4` เดิมคืนจาก `sim-runs/tune/history.jsonl` แล้วตรวจกับ `w3`: คะแนน 15.33, seed 75 ถึงด่าน 20 (183 kills), seed 164 ตายด่าน 7 **ตรงกับผลเดิมทุกค่า** ลิงก์ replay จึงกลับมาใช้ได้

## 2. `--reset` ล้มบน Windows

**อาการ:** `EPERM` ตอนเปลี่ยนชื่อโฟลเดอร์ `sim-runs/tune` (Windows ไม่ยอมให้เปลี่ยนชื่อโฟลเดอร์ที่ editor เปิดดูอยู่)

**แก้:** ถ้าเปลี่ยนชื่อไม่ได้ ให้คัดลอกไปเก็บที่ `<โฟลเดอร์>-archived-<เวลา>` แล้วล้างไฟล์ข้างในแทน

## 3. สมมติฐานของ LLM ติดไปกับ candidate อื่น

**อาการ:** ถ้า best มาจาก LLM ทุก candidate ที่ hill-climbing สร้างจาก best จะได้ `proposal` (สมมติฐาน + ผลที่คาด) ของ LLM ติดมาด้วย รายงานและ history จึงแสดงสมมติฐานผิดชุด (เห็นได้ใน history ของ `w4`)

**แก้:** candidate ใหม่ทุกตัว (hill, merge, `--try`) ไม่รับ `proposal` ของชุดต้นทาง
